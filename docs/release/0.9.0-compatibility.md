## Trigger and scope

The user's remote `kongserver` reports Nextcloud 35.0.2. Earlier app releases declare only Nextcloud 34, so they are not offered as compatible releases for that server generation. This task adds a compatible server target, not a new Media Storage REST version.

## API audit

Reviewed the official [Nextcloud 35 critical changes](https://docs.nextcloud.com/server/35/developer_manual/release_notes/critical_changes.html) and actual local source `version.php`: 35.0.2 / internal 35.0.2.2, Snap package 35.0.2snap2.

- Production migrations use the public ISchemaWrapper callback and scalar column type names. They work with the new ITable schema wrappers; no production Doctrine type signature changes are needed.
- The schema harness formerly returned Doctrine Table directly from a reflected interface double. It now returns the host's Table wrapper when ITable is present, retaining the older-host branch. Reflection doubles resolve interface `self` return types to the declaring interface rather than emitting invalid `\self`.
- The newer bundled SQLite/PDO requires finalizing the failed uniqueness-test statement before reuse. Added closeCursor in that test; constraints remain enforced and original data assertions remain unchanged.
- No removed Remote APIs, preview-provider registration, IRootFolder legacy emitter hooks, phpseclib namespace usage, or Symfony command subclasses are used by production code.
- Frontend requests use bundled @nextcloud/auth and @nextcloud/router imports, not the removed legacy `oc_*` aliases. HTTP-rendered session pages and previews work; no new browser UI/visual acceptance is claimed.
