## Changes

- GET/HEAD delivery now accepts API-token query credentials for virtual-path addressing. Old capability selectors/keys still use the existing pinned-resource service; legacy keys have no dot and are unambiguous from the ms_selector.secret credential format.
- Add header-authenticated external path GET/HEAD and path-based temporary-link POST returning only url/expires_at.
- Lookup runs under the verified token owner's existing lock. Restricted paths start at the exact token boundary; owner-wide paths default to Library or use an exact bucket name. No physical file path, owner input, recursive fallback, new database migration or file mutation is introduced.
- Existing MIME/permission checks, scope/revocation/expiry, range/conditional handling, cache/referrer headers, native request/resource/issuer limits, bounded streaming and cleanup leases apply. Query-token log/history/sharing exposure is documented; no real user token is used in tests or stored in the repo.
- MINOR version 0.10.0 for new API functionality. Google Photos metadata and Nextcloud 34–35 range remain.
